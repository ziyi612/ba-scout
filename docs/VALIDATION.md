# 验证范围

## 0.9.0 悬浮窗外观（2026-11-20）

在 Windows 原生窗口上使用同一组合成玩家数据对照旧版与新版。窗口为 748 × 580 像素。本机 125% 缩放下，选中玩家详情正文的可用高度从 8 像素增加到 78 像素。另以模拟 150% 缩放核对五行与工具栏布局。用 Windows 鼠标事件验证单击评分选中对应行、双击状态标签打开正确玩家的详情，并核对时间窗、数据汇总、收起及还原。

五人增量验收使用真实 Windows OCR、原生悬浮窗和本机测试 HTTP 服务。首次查名超时后，第二行显示补查并回填，其他玩家保持可见。真实游戏画面和公网响应随环境而异。界面预览中的姓名和数值均为演示数据。

## 0.8.0 准备阶段验收（2026-11-18）

五个合成昵称按第 0、3、6、9、13 秒的时间表在标准姓名位置出现。测试只向隔离的日志目录写入一条准备房间事件。程序使用真实 Windows OCR、姓名搜索和玩家页解析器、本机 HTTP 服务，以及 Windows 上的原生悬浮窗。所有战绩和比赛数据均由测试服务提供。

为了稳定复现整行查名超时，测试将单次搜索的最长等待设为 12 秒，并扣留第二行的首次 HTTP 响应 15 秒。首轮查名的 12 秒预算和首报的 20 秒预算采用正常值。程序在准备阶段再次读取相同姓名后自动补查，其他行继续显示。在五行表中采集实际可见的文本，并核对固定位置、测试账号、胜率以及两个时间窗的有效样本。

一次本机运行中，第一行在 3.59 秒显示胜率。第二行在 15.27 秒进入超时状态，19.02 秒确认身份，19.70 秒显示胜率。其余三人的胜率分别在 10.39、12.15、18.35 秒上屏。这些耗时适用于该次受控运行，真实 BATrace 加载速度和游戏画面识别率需另行观察。

复现命令为 `python -B tests/prep_acceptance.py`，逐行时间线与检查结果保存在 `work/acceptance/<运行时间>/result.json`。完整回归与打包验收的结果见对应版本的 Release 说明。

## 0.7.4 公开版本

2026-11-17 的公开版本基于已验证的 0.7.4 便携源码整理：移除游戏数据库和私人运行数据，将测试与构建路径改为项目目录，修正内部版本元数据，并使界面自测在缺少分类库时检查明确的缺失提示。

发布检查包括离线测试、Windows 便携程序构建、无分类库的运行环境检查、原生界面自测，以及发布文件的个人数据和压缩包完整性检查。具体本轮结果随 Release 列出。

测试仅证明所列输入下的行为，不保证未来网站接口不变、每次五个玩家都能唯一匹配、每人五场历史记录都能取得，或固定时间内始终返回相同数量的资料。

## 原 0.7.4 的历史验证（2026-10-29）

- 565 个独立程序测试覆盖通过。
- 原始准备截图按“占位→部分姓名→完整姓名”切换，运行真实 Windows OCR 和正常悬浮窗；两轮受控后端流程 49/49 检查通过。
- 受控后端采用明确的身份夹具和过去保存的响应，**没有联网**；其中第 24 秒才出现的名字也能继续补查，已有结果不消失或重查。
- 另一次真实联网测试仅能安全确认 3/5 名对手：一个名字无搜索结果，另一个存在多个完全同名账号；网站返回的累计统计字段也不完整。
- 上述联网测试取得部分基础资料与开局记录，不能称为“五人完整战绩验收通过”。

仓库不包含原始玩家截图、游戏日志、历史响应或个人报告。这里的历史记录也不是对当前日期网站状态的确认。

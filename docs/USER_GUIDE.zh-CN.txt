BA-Scout · 断箭战前情报 · Windows 便携分享版
使用说明书
文档日期：2026-11-17（公开源码版）

公开版说明：本仓库和公开程序包不包含从游戏数据库提取的单位分类资料。
仍显示公开对局返回的原始单位名称、出场次数、时间窗口、样本分母及基础类别。
坦克、防空等依赖额外分类库的角色汇总不可用时，会明确提示；不把无法分类写成零出场。
源码采用 MIT；Python、Tcl/Tk、PyInstaller 运行库按随包许可证分发，详见 THIRD_PARTY_NOTICES.md。

在准备阶段读取游戏里可见的对手昵称，逐人查公开历史资料；后出现的名字会自动补识别，已取得的资料保留。进入对局后，以游戏日志里的正式数字 ID 名单核对。软件只整合数据，不推荐卡组、不判断威胁、不预测本局出兵。

1. 第一次使用

1）完整解压 ZIP 到可写目录，例如 F:\Tools\BA-Scout。不要在压缩包内运行，也不要单独复制 EXE。
2）运行 BA-Scout.exe。保留 _internal、data、docs、licenses 等随包内容；不需要另外安装 Python。
3）首次向导选择自己的 GameLogs 文件夹，填写自己的游戏数字玩家 ID，或从最近名单中明确选择自己。分享包没有预设任何人的身份。
4）先开工具，再正常匹配。预设布局与游戏相同时，无须每局框选或点刷新；布局不同时，在“准备识别”里校准一次。
5）让游戏在前台正常显示，查看悬浮窗的“准备对手 x/5”和“战绩 x/5”。Ctrl+Alt+M 切换鼠标穿透／可操作，Ctrl+Alt+B 展开／收起。

2. 运行环境与个人配置

本包面向 Windows 10 / 11 x64，需要可读取的 Broken Arrow 普通游戏日志和可访问的 BATrace 公开网站。OCR 使用 Windows 本机语言引擎；其他电脑的语言组件、显示模式和显示比例仍需实际确认。游戏建议使用无边框全屏或窗口模式，普通置顶窗口在独占全屏下可能不可见。
Steam 库 → Broken Arrow → 管理 → 浏览本地文件 → GameLogs。选择文件夹本身，不是某一份 .log 文件。
数字玩家 ID 是日志 Player list 中的 ID 或已核实的 BATrace /player/ 后的数字，不是昵称，也不是 Steam 的 17 位 SteamID64。首次向导“读取最近名单”后，须自行选中自己；软件不会自动猜人。
没有最近名单时，可用自己已核实的数字 ID；或正常进入过一次对局后再从日志选择。换号或移动游戏库，在“设置”中修改。
配置、缓存、截图、日志、报告和临时文件都写在软件目录内。软件无须放进游戏目录，也不修改游戏文件、不读取游戏内存。

3. 准备阶段如何自动运行

程序从普通日志确认进入准备房间，随后读取已核验的前台游戏窗口。每个对手位置独立确认连续两帧稳定昵称；已有一人稳定就可开始查询，同时继续读取其余位置，不再在先识别三人后停止截帧。
Player name 等占位内容不会被当作玩家搜索。部分位置先显示真名、其他位置稍后显示时，后出现的位置自动补查。完成的人先显示；新增的人直接加入当前轮，不清空和重查已完成的玩家资料。
姓名查询保留实际识别到的拼写和必要的空格候选，逐个精确消歧。所有必要候选均完整返回、且唯一对应一个数字 ID 时才确认；同名多 ID、查询未完整完成、省略号或跨行等问题保留待确认。
经过核验的姓名框增加了一种亮度处理，改善部分中英混合名字。独立远端数字纹理只有在严格坐标与多个原名观测相互印证时才排除；真实相邻数字、同一 OCR 行里的数字后缀不会据此删除。实际标点候选继续保留，不凭相似字形改字认人。
当多个处理画面在相同坐标一致读到连续汉字，且其他语言只把这段汉字投影成符号时，这些结果保留为手动诊断，不重复用于姓名搜索。对姓名之外的前后缀、标点、坐标差异或多个来源一致支持的竞争拼写，不使用这个排除规则。只有逐词坐标证实紧邻的 OCR 插入空格才会合并；真实可见间隔和单词内部无坐标依据的空格保留。
同一名字首轮查名超时后，程序会在当前准备房间给该位置一次补查机会。已完成的拼写查询在本局复用。网站限流时等待共同冷却，新对局会取消上一局的补查。
同一位置稳定变成其他名字，或不同位置对应同一个 ID 时，旧身份会撤回，迟到的旧结果不能重新填回来。进入加载阶段后保留已显示的准备情报；正式数字 ID 名单到达后按该名单查询和核对。新局、对局结束或大厅状态会清空上一局的当前显示，旧 TXT 文件仍保留。
自动早期查询优先覆盖五名对手；队友资料主要在正式十人名单出现后补齐。界面会标记“准备画面姓名匹配，待游戏 ID 核对”，不要把屏幕匹配来源当作正式日志确认。

4. 姓名区域和手动校正

分享包带双方各五个独立姓名框的通用比例预设，不含截图、名字或个人 ID。相同比例布局通常可直接使用；UI 缩放、画面比例或界面排版变化时，仍可能需要校准。
按 Ctrl+Alt+M 允许操作 → “准备识别” → “设置自动识别区域”。读取当前完整游戏画面或载入只含完整游戏画面的 PNG，依次框五个对手、五个我方的完整昵称。不要包含头像、等级、Elo、倒计时；姓名框不能重叠或截断名字。保存后之后的对局继续沿用。
“名单校正 / 手动查询”可填完整昵称，或亲自从同名候选中选定正确的数字 ID。留空保持缺失，修改姓名会清除旧的 ID 选择。
名字被游戏本身截成省略号时，OCR 无法还原完整姓名；不要用猜测字符强行通过。纯数字、单汉字、同名和无法确认的候选可能需要手动核对。自己的 ID 出现在对手区域时先检查分组和姓名框。

5. 查询时间、请求数量和两种“20秒”

首批查询目标是在首个有效对手画面开始后的约20秒内给出已取得结果，截图与 OCR 耗时计入。它不是“保证20秒查齐五个人和每人五场”。
准备阶段每个新稳定位置都有有限的身份查询时间；后来才出现的名字可获得自己的补查窗口。因此首批约20秒之后仍可能有新增资料和更新报告，不能把这理解为首批计时被无限重置。相同未变化名字不会靠反复截帧无限续期。
自动准备识别每局最多30次姓名 HTTP 请求，每个位置最多12个必要候选；使用固定五个查询工作线程。一个人的多个候选会占多次请求，不等于可以查30个人。超出候选数不会截取部分拼写冒充完整核验。手动名单一次提交仍受较小请求上限控制。
单次姓名搜索最多请求50条候选。返回正好达到上限、返回数量不一致或必要查询失败时，保留待确认。HTTP 429 会共享冷却，至少60秒内暂停新增请求，不能用刷新绕过。
“前20秒出兵”是已结束历史比赛内 0≤t<20 秒的统计区间；“20秒查询目标”是软件等待查询的时间，两者完全不同。

6. 历史数据怎样读

默认同时统计固定前20秒与前120秒两个累计窗口，前120秒包含前20秒，不是20–120秒。两窗使用同批最近最多五场历史比赛，共享请求与缓存。
t＝网站单位部署时间 SpawnTime－比赛开始时间 StartTime，不是到达前线时刻，也不能证明鼠标购买顺序。同秒出现的单位不推断先后。
每个窗口分别计算有效样本。比赛太短、时序缺失、请求失败等不进入对应分母；足够长且完整、但窗内没有部署的比赛应计入分母。90秒比赛可支持前20秒，却不能支持前120秒。
“某型号 3/4局”表示取得的四场有效样本里，三场该窗口出现过此型号；不是下局概率。总出场次数包含该窗口记录的实例，不等于同时在场数量。只有一场时按单局记录阅读。
固定翼含无人机，旋翼含运输机及倾转机，车辆不等同于坦克。最近一场整场出场与开局窗口分开统计，返场实例仍计数，接收队友单位不重复加为自产出场。
排位胜率＝胜场÷排位总场数（含退局）；价值交换比＝摧毁价值÷损失价值；数量 K/D＝击杀单位数÷损失单位数。分母为零或字段缺失时显示未取得。
双专精经验是组合累计经验，不是近期使用率或本局卡组。国家经验也不是国家胜率。常用简称包括马润、特种、骑兵、装甲、空降、波波、vdv、国、近坦、海步、机械化、摩托化；完整名称与来源可在详情和 TXT 中查看。

7. 悬浮窗与报告

进入准备阶段默认显示五个对手位置。确认一人便在对应位置显示姓名，已取得的评分、胜率、双专精和历史开局型号陆续填入。默认观察前20秒，可切换前120秒。未确认的行显示查名进度或重名原因。缓存字段可在详情和 TXT 核对来源。
玩家页先提供近期对局编号时即可开始加载开局样本。本次读页中途缺少近期记录，会保留已有样本和来源。网站明确返回完整空清单时才清除这批记录。

Ctrl+Alt+B：展开／收起。Ctrl+Alt+M：鼠标穿透／允许操作。拖动标题栏可移动悬浮窗；不需要副屏。
“前20秒／第二窗口”：切换历史观察窗口。“全部单位 / 来源”或玩家详情：查看完整型号、样本数和来源。“看整场出场”：查看最近一场整场记录。
“打开战前报告”：打开当前生成的完整本地 TXT。“导出完整 TXT”：另存当前已有结果，并尝试复制为文件附件。“复制数据汇总”：复制文字。
自动报告保存在 exports 文件夹。名单增加或撤回后，当前报告引用相应更新，旧文件不会覆盖；看旧文件须核对对局 ID、生成时间与名单来源。
自动保存不会打开微信、粘贴或发送消息。若需要分享，由你自行在微信文件传输助手粘贴或拖入文件并发送。
“刷新本场”重查已有名单，不表示获取了新一局。“测试上局”明确属于历史名单回放，不等同于实战准备识别。按“退出”正常关闭；鼠标点不动时先按 Ctrl+Alt+M。

8. 缺失、缓存与排查

玩家资料有效缓存默认约十分钟；旧缓存会标记，不当作本轮刚抓取。历史比赛可复用更久，多名玩家或两个窗口共享同一比赛记录。
网站数据更新时间、本地抓取时间、比赛发生时间不同，应分别核对。未取得不代表零胜场、没使用某单位或没有历史记录。
网站有时只返回评分、排名和近期比赛编号，累计胜负与专精统计没有返回。此时界面标为“部分资料”，不会算入“战绩已齐”的人数；已取得的近期编号仍用于查询前20秒／前120秒出兵记录。若有此前完整缓存，继续明确显示旧缓存及其原时间，不把新评分与旧胜率拼成一份“刚查询成功”的资料，也不以部分返回覆盖完整缓存。
若仍只在进局后看到完整数据，先看准备阶段状态中的匹配人数与具体缺失原因：画面未抓到、姓名未稳定、名字歧义、搜索未完成是不同问题。data/runtime.log 会保留有界诊断；反馈版本、对局时间和具体状态即可，不必发送整个游戏日志。
游戏不在前台、最小化或画面不可用时，程序等待恢复，不主动切换你的游戏窗口。切回游戏后自动继续；不要在识别期间用其他窗口长期遮挡游戏。
如完全看不到悬浮窗，检查 Ctrl+Alt+B 是否收起、窗口是否移到屏幕外，并确认游戏使用无边框全屏／窗口模式。独占全屏的可见性须在本机验证。
启动报缺文件时完整重新解压并保留 _internal。快捷键冲突时不要同时运行多份工具；可在设置中更换。软件未进行发布者代码签名，系统提示时核对来源，不需要关闭杀毒软件。

9. 复制分享与验证边界

把完整分享 ZIP 发给对方。对方首次填写自己的 ID 与 GameLogs；不要把你已经运行过的 config.json、cache、截图、exports 或 runtime.log 再装进包里。
本版的软件测试、保存真实准备画面回放、真实联网验证和现场游戏验证是不同范围。随包验证记录只陈述本次实际完成的检查；保存截图验证不能替代另一台电脑、另一种显示布局或新一局现场测试。
没有保证每次五名对手全部识别、每人五场样本都取得，或始终在相同耗时内完成。最终以当前界面及报告列出的来源、有效样本数、缺失原因和抓取时间为准。
